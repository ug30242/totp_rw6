# Notify for Xiaomi 설치 오류 점검

대상은 사용자가 알려 준 **중국판 Redmi Watch 6 / 펌웨어 3.100.043 / Notify for Xiaomi**입니다. Notify의 정확한 앱 버전과 워치 연결 로그는 제공되지 않았습니다.

## 확인된 패키지 결함과 수정

첨부 ZIP 안의 debug·release RPK는 모두 같은 파일이었습니다. ZIP을 열 수 있고 `RPK Sig Block 42` 마커가 있다는 사실만으로 유효한 RPK가 되지는 않습니다.

독립 검증기 `scripts/verify-rpk.cjs`로 외부 서명 블록을 읽고, 서명이 기록한 패키지 콘텐츠 해시를 ZIP 본문·중앙 디렉터리·복원한 EOCD로 다시 계산했습니다. 첨부 파일은 **`RPK content digest mismatch`**로 실패했습니다. `tests/fixtures/original-invalid.rpk`는 이 문제의 재발 방지용 원본 파일이며 설치용으로 배포하지 않습니다.

공식 `aiot release`로 새로 만든 `1.0.1` 패키지는 다음을 통과합니다.

- 외부 패키지의 RSA-SHA256 서명 및 콘텐츠 해시
- 서명된 파일 목록, 개별 파일의 SHA-256, ZIP CRC
- 내부 `META-INF/CERT`의 서명과 `hash.json` 파일 목록
- 내부·외부 인증서 일치 및 기존 공개 인증서와의 일치
- `manifest-watch.json`, 공식 컴포넌트 엔트리, 페이지·아이콘, 버전 `1.0.1` / 코드 `2`

버전이 고정된 공식 도구로 빌드하고 검증에 실패하면 배포를 중단합니다. 원본 파일 이름을 바꾸거나 ZIP으로 다시 압축하는 방식은 사용하지 않습니다.

이는 **실제 확인한 패키지 결함의 수정**입니다. 폐쇄 소스인 Notify의 파일 인식 경로와 실기기 설치 결과까지 재현한 것은 아니므로 이 오류 메시지의 모든 원인이 해결됐다고 단정하지 않습니다.

## 1.0.2 앱 진입 시 검은 화면

사용자 확인으로 1.0.1의 Notify 설치는 통과했으나 실행하면 검은 화면이 나왔습니다. 배포된 RPK의 컴포넌트 진입점을 Node CommonJS 전역 없이 실행한 결과 `ReferenceError: exports is not defined`를 재현했습니다. 루트 `package.json`의 `type: module`과 aiot-toolkit의 CommonJS 변환 결과가 충돌하여, 모듈의 `exports`와 상대 경로 `require()`가 번들 내부 모듈로 처리되지 않은 것이 원인입니다.

1.0.2는 해당 설정을 제거하고 공식 도구로 다시 빌드했습니다. 기존 1.0.1 파일은 같은 실행 검사에서 실패하고 새 파일은 통과합니다. 빈 홈 화면, 기존 RFC 계정의 OTP 표시, 저장소 오류 표시, QR 화면 초기화와 타이머 정리를 검사합니다. 이는 컴파일된 코드와 화면 바인딩 검사이며 실제 워치의 네이티브 UI 재현은 아닙니다.

**현재 설치용 파일은 `com.vela.rw6totp.release.1.2.0.rpk` (versionCode 6)입니다.** 같은 앱 식별자와 인증서를 유지했으므로 기존 계정을 보존하는 업데이트를 먼저 시도하세요. 검은 화면 해결을 위해 앱 데이터 삭제나 서명키 변경을 할 필요는 없습니다.

## 1.0.3 한글과 기호 깨짐

이전 버전의 홈 화면이 표시되지만 한글이 깨진다는 사용자 보고에 따라 워치 기본 폰트에서 표시 가능한 ASCII 영어로 UI·오류 메시지를 통일했습니다. 별도의 한글 폰트는 포함하지 않습니다. 계정 이름은 저장 원문을 유지하면서 화면에서 ASCII 부분 또는 Account N으로 표시합니다. 이는 앱에서 사용하는 문자 범위를 제한하는 해결책이며 펌웨어의 한글 지원 여부 전체를 판정하는 것은 아닙니다.

## 설치 후 확인할 내용

1. 워치 설치에는 릴리스의 `com.vela.rw6totp.release.1.2.0.rpk`를 다운로드합니다. 브라우저가 HTML 오류 페이지를 저장하지 않았는지, 확장자가 `.rpk`인지 확인합니다.
2. 릴리스의 `SHA256SUMS`와 파일 해시를 비교합니다. PC에서는 릴리스 파일이 있는 디렉터리에서 `sha256sum -c SHA256SUMS`로 확인할 수 있습니다.
3. Notify for Xiaomi의 **펌웨어 업데이트 → 타사 앱(RPK)**에서 이 RPK를 직접 선택합니다. 원본 첨부 ZIP이나 GitHub의 Source code ZIP을 선택하지 않습니다.
4. 선택 직후 `invalid firmware file`이 발생하면 **Notify 앱 버전, 파일명·바이트 크기·SHA-256, 오류 화면과 파일 선택 직후 로그**를 확보합니다. 휴대폰에서 파일이 읽히는지와 Notify의 해당 기종 RPK 지원을 구분해야 합니다. 개인키·TOTP 키·페어링 URL은 로그에서 제거하세요.
5. 파일 선택은 통과하고 워치 전송/설치 단계에서 실패하면 워치의 반환 오류, 펌웨어의 앱 설치 제한과 서명 정책을 확인해야 합니다. 패키지 해시 검사를 통과했다는 사실만으로 기기 정책 호환성을 입증할 수는 없습니다.
6. 실행되면 테스트 계정으로 원본 인증기와 OTP가 일치하는지, 순서 변경·삭제 확인·재실행 후 데이터 유지가 되는지 확인합니다. 기존 계정이 있다면 삭제·재설치 전에 원본 인증기와 복구 수단을 보존하세요.

사용자 확인: 이전 버전의 Notify 설치와 홈 화면 진입. 이 클라우드 환경에서 직접 검증하지 않은 항목: 새 버전의 실기기 글리프·레이아웃, 실제 워치 저장소와 Mi Fitness 통신.

## 1.1.0 QR 링크 404와 서버 없는 등록

이전 페이지는 배포가 필요한 GitHub Pages 주소를 워치 QR에 고정했고 ntfy 중계로 계정을 전달했습니다. 1.1.0은 이 경로와 네트워크 권한을 제거하고 워치 직접 입력과 오프라인 QR 도우미로 전환합니다. 현재 설치용 파일은 `com.vela.rw6totp.release.1.1.0.rpk` (versionCode 5)입니다. 앞선 버전의 파일명과 QR 경로는 문제 이력입니다.

도우미 `totp-import.html`을 다운로드하여 브라우저에서 열고 원본 TOTP QR 이미지/URI에서 Secret·Hash·Digits·Period를 확인하세요. 워치의 + Add에 직접 입력합니다. 휴대폰에서 워치로 자동 전송하는 기능은 포함하지 않습니다. 웹 주소 QR은 계정 QR로 취급하지 않고 이동하지도 않습니다. 실제 워치의 입력 UI/터치 동작은 확인 대상입니다.

## 1.2.0 Android 계정 동기화

현재 버전은 `com.vela.rw6totp.release.1.2.0.rpk` (코드 6)와 `rw6-totp-android-1.2.0.apk`입니다. 앞선 1.1.0 등록 절차는 이력입니다.

Android에서 계정을 직접 추가한 뒤 동기화합니다. QR은 선택 사항이며 워치의 QR이나 웹 링크를 사용하지 않습니다. Notify는 RPK 설치에 사용하고, 동기화는 Mi Fitness / 중국판 운동건강의 XMS 서비스를 사용합니다. 두 패키지의 앱 ID와 기존 인증서를 일치시켰습니다. 기기 통신 권한 확인, 수신 준비 핸드셰이크, 실제 저장 후 응답, 안정적인 항목 ID로 갱신을 구현했습니다. 자동 화면 실행이 되지 않으면 워치의 + Phone을 열고 동기화합니다.

클라우드 검증은 APK·RPK 빌드/서명, 컴파일된 화면, Android 패킷→워치 저장→RFC OTP, 오류·갱신·중복 회귀까지입니다. 실제 펌웨어 3.100.043, 해당 Mi Fitness의 XMS 서비스, Bluetooth 및 Android Keystore·카메라는 실기기 확인 대상입니다. 연결 실패 메시지에서 인증키와 계정 내용을 노출하지 않습니다.
