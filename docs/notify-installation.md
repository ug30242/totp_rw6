# Notify for Xiaomi 설치 오류 점검

대상은 사용자가 알려 준 **중국판 Redmi Watch 6 / 펌웨어 3.100.043 / Notify for Xiaomi**입니다. Notify의 정확한 앱 버전과 워치 연결 로그는 제공되지 않았습니다.

## 확인된 패키지 결함과 수정

첨부 ZIP 안의 debug·release RPK는 모두 같은 파일이었습니다. ZIP을 열 수 있고 `RPK Sig Block 42` 마커가 있다는 사실만으로 유효한 RPK가 되지는 않습니다.

독립 검증기 `scripts/verify-rpk.cjs`로 외부 서명 블록을 읽고, 서명이 기록한 패키지 콘텐츠 해시를 ZIP 본문·중앙 디렉터리·복원한 EOCD로 다시 계산했습니다. 첨부 파일은 **`RPK content digest mismatch`**로 실패했습니다. `tests/fixtures/original-invalid.rpk`는 이 문제의 재발 방지용 원본 파일이며 설치용으로 배포하지 않습니다.

공식 `aiot release`로 새로 만든 `1.0.1` 패키지는 다음을 통과합니다.

- 외부 패키지의 RSA-SHA256 서명 및 콘텐츠 해시
- 서명된 파일 목록, 개별 파일의 SHA-256, ZIP CRC
- 내부 `META-INF/CERT`의 서명과 `hash.json` 파일 목록
- 내부·외부 인증서 일치 및 기존 공개 인증서와의 일치
- `manifest-watch.json`, 공식 컴포넌트 엔트리, 페이지·아이콘, 버전 `1.0.1` / 코드 `2`

버전이 고정된 공식 도구로 빌드하고 검증에 실패하면 배포를 중단합니다. 원본 파일 이름을 바꾸거나 ZIP으로 다시 압축하는 방식은 사용하지 않습니다.

이는 **실제 확인한 패키지 결함의 수정**입니다. 폐쇄 소스인 Notify의 파일 인식 경로와 실기기 설치 결과까지 재현한 것은 아니므로 이 오류 메시지의 모든 원인이 해결됐다고 단정하지 않습니다.

## 설치 후 확인할 내용

1. 릴리스에서 `com.vela.rw6totp.release.1.0.1.rpk`만 다운로드합니다. 브라우저가 HTML 오류 페이지를 저장하지 않았는지, 확장자가 `.rpk`인지 확인합니다.
2. 릴리스의 `SHA256SUMS`와 파일 해시를 비교합니다. PC에서는 릴리스 파일이 있는 디렉터리에서 `sha256sum -c SHA256SUMS`로 확인할 수 있습니다.
3. Notify for Xiaomi의 **펌웨어 업데이트 → 타사 앱(RPK)**에서 이 RPK를 직접 선택합니다. 원본 첨부 ZIP이나 GitHub의 Source code ZIP을 선택하지 않습니다.
4. 선택 직후 `invalid firmware file`이 발생하면 **Notify 앱 버전, 파일명·바이트 크기·SHA-256, 오류 화면과 파일 선택 직후 로그**를 확보합니다. 휴대폰에서 파일이 읽히는지와 Notify의 해당 기종 RPK 지원을 구분해야 합니다. 개인키·TOTP 키·페어링 URL은 로그에서 제거하세요.
5. 파일 선택은 통과하고 워치 전송/설치 단계에서 실패하면 워치의 반환 오류, 펌웨어의 앱 설치 제한과 서명 정책을 확인해야 합니다. 패키지 해시 검사를 통과했다는 사실만으로 기기 정책 호환성을 입증할 수는 없습니다.
6. 실행되면 테스트 계정으로 원본 인증기와 OTP가 일치하는지, 순서 변경·삭제 확인·재실행 후 데이터 유지가 되는지 확인합니다. 기존 계정이 있다면 삭제·재설치 전에 원본 인증기와 복구 수단을 보존하세요.

실기기에서 확인하지 않은 항목: Notify 파일 인식, BLE 전송, 펌웨어 3.100.043의 서명 허용, 워치 UI 렌더링, 실제 워치 저장소와 네트워크 중계.
